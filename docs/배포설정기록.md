# 배포·설치 후 설정 기록 — 착한가격 지도

> 2026-09-21 첫 배포 때 실제로 한 설정과 겪은 함정을 순서대로 기록한다.
> 목적: ① 이 프로젝트 운영(주소·키 변경 시 참고) ② **다음 프로젝트의 체크리스트·스킬·기본 지침 원자료.**
> 키·계정 이메일·계정 ID 같은 개인 정보는 적지 않는다(공개 저장소).

---

## 1. 구성 한눈에

| 역할 | 서비스 | 비용 | 비고 |
|---|---|---|---|
| 코드 보관 | GitHub (공개 저장소) | 무료 | `main`에 올리면 자동 배포 |
| 사이트 + 서버 기능 | Cloudflare Pages + Pages Functions | 무료 (하루 10만 요청, 파일 2만 개) | 카드 등록 없음 |
| 지도·장소·공유 | 카카오 지도 JS SDK, 카카오톡 공유(Kakao SDK) | 무료 | 도메인 등록 3곳 |
| 문장 해석 AI | Google Gemini API (무료 등급) | 무료 | 결제 미연결 = 과금 불가 |
| 방문 통계 | Cloudflare Web Analytics | 무료 | 쿠키 없음 |

- 배포 폴더는 `app/`, 서버 기능은 `functions/`(Cloudflare가 자동 인식), 설정 파일 `wrangler.toml`.
- 파이썬 서버(`server.py`)는 **로컬 개발용**이며 배포되지 않는다.

## 2. 설정 순서와 내용

### 2-1. 배포 전 준비 (저장소)
| 항목 | 한 일 | 주의 |
|---|---|---|
| 제외 목록 | `.gitignore`: `.env`, 키 메모 파일, 원본·중간 데이터, 검증 결과, 엑셀, `.dev.vars`, `.wrangler/` | **꼭 올려야 하는 파일은 예외로 명시**(`!data/processed/id_registry.json` 등) |
| 키 검사 | 올라갈 텍스트 파일 전체를 `.env`의 실제 키 값과 대조 → 0건 확인 후 업로드 | 패턴 검사만으로는 부족, **실제 값 대조**가 확실 |
| 커밋 작성자 | 이메일을 GitHub 비공개 주소(`아이디@users.noreply.github.com`)로 설정 | 개인 메일이 공개 기록에 남지 않게 |
| 대용량 | 사진 축소본 1.2만 장(약 200MB) 포함, `http.postBuffer` 확장 | 첫 업로드는 로그인 창 승인 필요 |

### 2-2. GitHub
1. 새 저장소 생성(Public). **README·.gitignore 추가 옵션은 끄기**(로컬에 이미 있음).
2. 로컬에서 원격 연결 후 push → 첫 push 때 Git 로그인 창(브라우저)에서 승인.
- 참고: 저장소 이름에 오타(끝의 `-`)가 있어도 사이트 주소는 Cloudflare 프로젝트 이름으로 정해지므로 영향 없음.

### 2-3. Cloudflare Pages
| 단계 | 경로 / 값 | 함정 |
|---|---|---|
| 가입 | 이메일·비밀번호, 메일 인증 | 카드 등록 없음 |
| 프로젝트 만들기 | 컴퓨트 → **Workers 및 Pages** → 생성 → 화면 맨 아래 **"Pages를 배포하려고 하십니까? 시작"** → Git 리포지토리 가져오기 | 기본 화면은 **Workers용**. 여기서 "Connect GitHub"를 누르면 Pages가 아님. 파일 끌어다 놓기(업로드)도 쓰지 말 것(자동 배포·Functions 없음) |
| GitHub 권한 | Only select repositories → 해당 저장소만 | 전체 저장소 권한 주지 않기 |
| 빌드 설정 | 프로젝트 이름 = 사이트 주소(`이름.pages.dev`), 프레임워크 **없음**, 빌드 명령 **비움**, 출력 디렉터리 **`app`** | 이름은 공유 링크 주소가 되므로 신중히 |
| **API 키** | 설정 → 변수 및 비밀 → 유형 **비밀(Secret)**, 이름 `GEMINI_KEY`, 프로덕션 | 첫 화면의 "환경 변수"에 **일반 텍스트로 넣으면 적용 안 됨**(`wrangler.toml`이 있으면 일반 변수는 설정 파일 기준). 비밀로 등록 후 **재배포** 필요. 키가 보이는 화면은 캡처 금지 |
| 재배포 | 빈 커밋 push (`git commit --allow-empty`) | 설정·비밀 변경은 새 배포부터 적용 |
| 빌드가 안 끝날 때 | GitHub 커밋 옆 Cloudflare 체크(또는 API `commits/{sha}/check-runs`)로 상태 확인 | 드물게 빌드가 20분 넘게 멈췄다 실패함 → 재빌드하면 정상. push 후 **배포된 버전(파일 주소의 ?v= 값)을 확인**하는 습관 |
| 목록에 프로젝트가 안 보일 때 | 새로고침(↻) 또는 `dash.cloudflare.com/<계정ID>/pages/view/<프로젝트>` | 화면 갱신 지연 |
| 방문 통계 | 프로젝트 → Web Analytics 켜기 | 선택 |

### 2-4. 카카오 개발자 콘솔 — 도메인 3곳
| 위치 | 용도 | 등록 값 |
|---|---|---|
| 앱 → **플랫폼 키 → JavaScript 키 → 도메인** | 지도 SDK 동작 | 배포 주소, `http://localhost:8000`, `http://127.0.0.1:8000`, 휴대폰 테스트용 `http://<PC IP>:8000` |
| 앱 → **제품 링크 관리** | **카카오톡 공유 메시지의 링크**가 열리게 | 배포 주소 |
| 앱 → 일반 → 앱 기본 정보 → **앱 대표 도메인** | 앱 대표 정보 | 배포 주소 |
- 함정: JavaScript 키 도메인만 있으면 공유 **메시지는 가지만 링크가 안 열림**(링크가 빠진 채 전송). 제품 링크 관리 등록 후 **새로 보낸 메시지부터** 열림.
- 휴대폰 테스트 IP는 공유기가 바꿀 수 있음(192.168.1.5 → 192.168.0.4 사례) → 바뀌면 재등록.
- 콘솔 URL: `https://developers.kakao.com/console/app`

### 2-5. Google Gemini
| 항목 | 내용 |
|---|---|
| 키 보관 | 로컬 `.env`, 배포 Cloudflare 비밀. 브라우저 코드에는 절대 넣지 않음(서버 기능이 중계) |
| 결제 | Google AI Studio에서 **결제 미연결** 확인 → 한도 초과 시 과금 대신 실패, 앱은 규칙 해석으로 자동 대체 |
| 모델 | `gemini-3.1-flash-lite` (모델은 주기적으로 종료됨 → `functions/api/parse.js`의 `MODEL`) |
| 키 노출 시 | 새 키 발급 → `.env`·Cloudflare 두 곳 교체 |

### 2-6. 홈 화면 추가(PWA)
| 항목 | 설정 | 이유 |
|---|---|---|
| manifest | `name`, `short_name`, `start_url`, `scope`, `display: standalone`, 아이콘 192·512(any + maskable) | 설치 조건 |
| `id` | 첫 배포 후 `"/?src=home"`로 **고정** | 나중에 바꾸면 이미 설치한 폰에서 다른 앱으로 인식 |
| `handle_links: preferred`, `launch_handler` | 안드로이드: 사이트 링크를 설치된 앱으로 열기, 열린 창 재사용 | 폰(OS)이 최종 결정. 카카오톡·아이폰은 적용 안 됨 |
| 서비스워커 | 네트워크 우선, `/api/`·외부 요청 제외 | 설치 조건 + 옛 파일 고착 방지 |
| 설치 유도 | 첫 화면 버튼, 더보기 맨 위, **업소를 본 뒤 한 번** 제안(7일 유예), 설치했으면 숨김 | 링크 진입 시 **먼저 묻지 않음**(이탈·검색 불이익) |
| 브라우저별 안내 | 크롬·웨일·삼성 인터넷·엣지·파이어폭스·아이폰 사파리·앱 안 브라우저 구분 | 설치 창이 없는 브라우저 대비 |
| 앱 안 브라우저 | 카카오톡 등에서 열리면 "브라우저로 열기"(`kakaotalk://web/openExternal?url=`) | 카톡 안에서는 설치·위치 제한 |

### 2-7. 공유 미리보기(카카오톡 등)
- `functions/_middleware.js`가 첫 화면의 OG 태그를 채움: 기본은 대표 이미지, 공유 링크(`?s=&id=`)면 업소명·대표 메뉴 가격·주소·축소본 사진.
- 카카오톡 공유 버튼은 Kakao SDK `Share.sendDefault`(feed) — 제품 링크 관리 등록 필요.
- 미리보기가 옛것으로 나오면 카카오 공유 디버거에서 캐시 초기화.

### 2-8. 외부 사이트 수집이 배포 환경에서 막히는 경우
- 공식 누리집 공지 목록: PC에서는 수집되지만 **Cloudflare에서는 1.5KB짜리 짧은 페이지**(클라우드 접속 차단 추정).
- 대응: PC에서 `update_notices.py`로 받아 `app/data/notices.json`으로 함께 배포, 서버 기능은 실시간 실패 시 이 파일 사용.
- 교훈: **공공기관 사이트는 클라우드 접속을 막을 수 있다 → 배포 환경에서 외부 수집을 먼저 확인, 항상 저장본 대체 경로.**

### 2-9. 로컬 개발·테스트
| 목적 | 방법 |
|---|---|
| PC에서 보기 | `python server.py 8000` → `http://localhost:8000` |
| 휴대폰(같은 와이파이) | `python server.py 8000 --lan` → 표시되는 `http://<PC IP>:8000`, 카카오 JS 키 도메인에 등록, 윈도우 방화벽 "개인 네트워크 허용". GPS·홈 화면 추가는 https가 아니라 불가 |
| 배포와 같은 환경(Cloudflare) | `npx wrangler pages dev --port 8788` + `.dev.vars`(키, 저장소 제외) |
| PC 브라우저로 휴대폰 흉내 | 크롬 F12 → Ctrl+Shift+M → 기기 선택 |
- 함정: 명령줄(curl)로 한글을 보내면 인코딩이 깨져 AI가 엉뚱하게 해석 → **한글 테스트는 브라우저에서.**
- 함정: 자동화 테스트 브라우저 창이 가려지면 페이지가 hidden 상태 → 화면 그리기·애니메이션·IntersectionObserver가 멈춰 "사진 안 뜸, 목록 안 접힘"처럼 보임(실제 버그 아님). 화면을 띄운 상태로 확인.

### 2-10. 검색 사이트 등록 (2026-09-22)
| 곳 | 한 일 | 함정 |
|---|---|---|
| 구글 서치 콘솔 | 속성 추가 → **URL 접두어** `https://goodprice-map.pages.dev/` → 확인 방법 **HTML 태그** → 태그를 `app/index.html` `<head>`에 넣고 배포 → 확인 → Sitemaps에 `sitemap.xml` 제출 | pages.dev는 DNS를 못 바꾸므로 "도메인" 방식 불가. 태그 칸은 입력칸이 아니라 **[복사]** 용. [완료]를 누르면 속성 미선택 화면으로 돌아가므로 왼쪽 위 속성 목록에서 다시 선택. 제출 직후 "가져올 수 없음"은 정상(처리 대기) |
| 네이버 서치어드바이저 | 웹마스터 도구 → 사이트 등록 → 소유확인 **HTML 태그** → 같은 방식으로 넣고 배포 → 소유확인 → 요청 → 사이트맵 제출 `https://goodprice-map.pages.dev/sitemap.xml` → 요청 → 웹 페이지 수집에 첫 화면 주소 요청(첫 수집 앞당김) | 기본 선택이 "HTML 파일 업로드"라 태그로 바꿔야 함 |
- 확인 태그는 **지우지 않는다**(지우면 확인이 풀림). 두 태그 모두 공개 값이라 저장소에 있어도 된다.
- `app/sitemap.xml`(대표 주소 1개) + `app/robots.txt`의 `Sitemap:` 줄. 업소별 개별 페이지가 없어 수집 효과는 제한적(첫 화면만 검색 노출).
- 태그를 넣은 뒤 검색 로봇과 같은 방식(Googlebot·Yeti 식별값)으로 첫 페이지와 사이트맵을 열어 태그·응답(200, application/xml)을 확인했다.
