# 운영 절차 — 착한가격 지도

> 분기 1회 데이터 업데이트와 배포, 문제 대응 방법. 명령은 모두 프로젝트 폴더에서 실행한다.
> 원칙: **번호 대장(`data/processed/id_registry.json`)은 절대 지우거나 새로 만들지 않는다.** 지우면 저장·공유 링크가 전부 다른 가게를 가리킨다.

---

## 1. 분기 업데이트 (약 반나절, 대부분 자동 대기)

### 1-1. 준비
1. 공공데이터포털 "행정안전부_착한가격업소 현황"의 수정일이 지난 업데이트 이후인지 확인한다.
2. **백업:** `data/` 폴더 전체를 외장 디스크나 개인 클라우드에 복사한다(원본·중간 데이터는 GitHub에 올라가지 않는다).
3. `.env`의 API 키가 살아 있는지 확인한다(카카오 REST, 네이버, 도로명주소, 공공데이터포털, 제미나이).

### 1-2. 수집 → 결합 → 검증 (순서대로)
| 순서 | 명령 | 하는 일 | 비고 |
|---|---|---|---|
| 1 | `python collect_goodprice.py` | 공식 사이트 목록·지도 데이터 수집 | 요청 간격 유지 |
| 2 | 공공데이터 CSV를 `data/raw/datagokr_goodprice.csv`로 교체 | 공공데이터포털에서 새 파일 내려받기 | |
| 3 | `python build_master.py` | 두 출처 결합, **번호 대장으로 관리번호 부여** | 새 업소만 새 번호 |
| 4 | `python fix_coords.py` | 좌표 보정 | |
| 5 | `python match_kakao.py` | 카카오 장소 매칭(이전 결과는 관리번호로 재사용) | 새 업소 위주로 실행 |
| 6 | `python verify_naver.py` · `verify_phone.py` · `check_address.py` · `verify_sbiz.py` | 교차 검증 | 결과는 공개 저장소에 올리지 않음 |
| 7 | `python build_final.py` | 검증 결과 반영 | |
| 8 | `python collect_details.py` | 영업시간·메뉴·사진 주소 수집 | 새 업소 위주 |
| 9 | `python build_app_data.py` | 앱용 통합 데이터 | |
| 10 | `build_web_data.py`의 `meta['updated']`를 이번 기준일로 수정 후 `python build_web_data.py` | 시도별 앱 데이터 생성 | 기준일이 바뀌어야 사용자 브라우저가 새 데이터를 받음 |
| 11 | `python gen_thumbs.py` | 새·바뀐 사진만 축소본 생성, 빠진 업소 축소본 정리 | 처음이 아니면 수십 분 |
| 12 | `python update_notices.py` | 공식 소식(공지 제목·날짜) 저장 → `app/data/notices.json` | 공식 누리집이 클라우드 접속을 막아, 배포 서버 대신 PC에서 받아 올림. 새 공지가 있을 때도 실행 후 배포 |

### 1-3. 검사 (통과해야 배포)
```
python check_data.py
```
- **FAIL이 있으면 배포하지 않는다.** 메시지대로 원인을 고친 뒤 다시 실행.
- 자주 나오는 경우:
  - `지난 배포보다 N곳 빠짐(10% 초과)` → 원본 형식(열 이름)이 바뀌었을 가능성. 1-2의 2·3단계 확인.
  - `같은 ID의 업소명이 바뀐 곳` 다수 → 번호 대장이 손상됐거나 다른 파일을 쓴 것. 백업의 `id_registry.json` 복원.
  - `오픈=마감` → `build_web_data.py`의 `fix_hours` 규칙 보강.
  - `시군구 형식 이상` → `norm_sgg` 규칙 보강.
  - `시도 줄임말 사전에 없는 시도` → 행정구역 변경. `app/intro.js`의 `SIDO_ALIAS`에 추가.
  - `알 수 없는 업종` → 공공데이터 업종 체계 변경. `check_data.py`의 `UPJONG`과 `app/app.js`의 `GROUPS`(업종 묶음)에 추가(안 하면 앱에서는 "생활"로 보임).
  - `알 수 없는 한식 세부분류` → `app/app.js`의 `SUBS`와 `check_data.py`의 `HANSIK_SUB`에 추가.
- WARN은 읽어 보고 판단한다(상호 변경, 축소본 누락 등).

### 1-4. 화면 확인 (로컬)
1. `python server.py 8000` 실행 → http://localhost:8000
2. `docs/버그이력.md` 부록의 **회귀 테스트 문장**을 검색창에 넣어 기대 결과와 같은지 확인.
3. 저장해 둔 업소가 같은 가게로 열리는지, 새 업소가 지도에 보이는지 확인.

### 1-5. 배포
1. 검사 통과 기준 저장: `python check_data.py --accept`
2. GitHub에 올리기(변경 파일: `app/data/`, `app/thumbs/`, `data/processed/id_registry.json`, `thumbs_manifest.json`, `last_ids.json`, 스크립트 수정분).
3. Cloudflare가 자동 배포 → 배포 주소에서 1-4의 확인을 한 번 더.
4. 더보기 → "데이터 기준"이 새 날짜로 바뀌었는지 확인.
5. 문서(docs/, README)를 고쳤으면 `python check_docs.py`로 문서 정합성 확인(FAIL 0건이어야 올림). 점검 항목은 [지식화 프로세스](지식화-프로세스.md) 4장.

## 2. 업소 제외 요청 처리
- 기준(사용자 결정): **행정안전부 착한가격업소(goodprice.go.kr)에서 조회되지 않으면 제외.** 공공데이터 활용 기준을 따른다.
- 조회되면: 공식 지정 업소이므로 유지하고, 정보 수정은 공식 사이트의 "업소정보 오류 신고" 또는 해당 시군구 담당부서로 안내.
- 제외 방법: `data/exclude_ids.json`에 `{"id": "GP00000", "reason": "공식 사이트 미조회", "date": "YYYY-MM-DD"}` 형식으로 추가 → `build_web_data.py` 재실행 → 검사 → 배포. **번호 대장에서는 지우지 않는다**(번호 재사용 방지).

## 3. 문제 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 지도가 안 뜸 | 카카오 콘솔의 JavaScript 키 도메인 | 배포 주소 등록 |
| 카카오톡 공유 링크가 안 열림 | 카카오 콘솔 → 앱 → 제품 링크 관리 | 배포 주소 등록 후 새 메시지로 확인 |
| 사이트 주소를 바꿀 때 | 카카오 콘솔 세 곳: JavaScript 키 도메인, 제품 링크 관리, 앱 대표 도메인 | 새 주소 모두 등록(옛 주소는 전환 기간 동안 유지) |
| 문장 검색이 AI 해석을 안 함 | 제미나이 한도·모델 이름 | 모델이 종료됐으면 서버 코드의 모델명 교체. 그동안은 규칙 해석으로 자동 동작 |
| 공식 소식이 안 보임 / 오래됨 | 공식 사이트 공지 목록 구조 변경, 또는 저장된 목록이 오래됨 | `python update_notices.py` 후 배포. 실패하면 수집 정규식(`server.py`의 `fetch_notices`, `functions/api/notices.js`의 `parse`) 수정 |
| 목록 사진이 안 보임 | `app/thumbs/`에 파일이 있는지 | `python gen_thumbs.py` 재실행 |
| 공유 미리보기가 옛것 | 카카오톡 미리보기 캐시 | 카카오 공유 디버거에서 초기화 |
| 배포 후 큰 문제 | — | Cloudflare Pages의 이전 배포로 되돌리기(Rollback) |
| push했는데 사이트가 안 바뀜(빌드가 오래 "진행 중" 후 실패) | GitHub 커밋의 Cloudflare 체크 상태, 또는 대시보드 → 배포 | Cloudflare 쪽 일시 장애일 수 있음(2026-09-21 사례: 20분+ 후 실패, 같은 내용 재빌드는 1~2분 성공). 빈 커밋 push(`git commit --allow-empty`) 또는 대시보드에서 **다시 시도(Retry)** |

## 4. 키 교체
1. 새 키 발급 → `.env` 수정(로컬), Cloudflare 환경변수(Secrets) 수정(배포).
2. 카카오 JavaScript 키가 바뀌면 `app/index.html`의 SDK 주소도 수정.
3. 키는 채팅·문서·GitHub에 붙여넣지 않는다.
