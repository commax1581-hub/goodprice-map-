# 분류 체계 × 자연어 검색 × AI 매핑 — 재사용 모듈

> **모듈 문서:** 다른 프로젝트에서도 가져다 쓰는 설계를 모은 문서다. 착한가격 지도는 첫 적용 사례이고, 근거는 [사례지식](사례지식.md) 장 번호와 [버그이력](버그이력.md) 번호(#)로 연결한다.
> 대상 상황: 원본 데이터의 분류가 **행정·공급자 기준**이라 사용자가 쓰는 말과 다를 때(업종, 시설 유형, 민원 분류, 상품 분류 등).
> 사건 기록(증상·원인·해결)은 버그이력, 이 문서는 **원칙과 근거 번호**만 담는다. 갱신 규칙은 8장.

---

## 0. 한눈에

| 문제 | 해법 |
|---|---|
| 원본 분류(업종 12개)가 사용자 머릿속 분류와 다르다 | 데이터는 그대로, **화면 층에서 묶는다**(묶음 + 세부 칩) |
| 사람은 "머리 자르고 싶어", "부산 막걸리"처럼 말한다 | **규칙 사전 먼저, 못 읽으면 AI**, 모르는 단어도 버리지 않고 검색어로 |
| AI 답은 흔들리고, 없는 값도 만든다 | AI는 **데이터에 있는 값으로만** 답하게 하고, 앱이 재검증·변환 |
| 해석은 맞는데 결과가 0곳 | 조건을 하나씩 풀어 다시 찾고 **뺀 조건을 알려준다** |

핵심 성과: 업종 칩을 13개에서 8개로 다시 묶었지만(2026-09-22) **AI 프롬프트·서버 함수는 한 줄도 고치지 않았다**. 층을 나눠 둔 덕분이다.

## 1. 층 구조

```
[언어 층]   사람의 말: "머리 자르고 싶어" "종로 이발소" "카페" "부산 막걸리"
     │  ① 규칙 해석(브라우저, 즉시·무료) → 읽은 조건이 1개 이하면 ② AI 해석
[AI 층]     AI는 데이터 값으로만 답함 (업종 12개 JSON 스키마) → 앱이 허용 목록으로 재검증
     │  ③ 변환: 데이터 값 → 화면 값 (catOf)
[표시 층]   분류 체계: 칩 8개(묶음 3개 포함) + 세부 칩 — 묶음 표(GROUPS) 하나
     │  ④ 필터(matchCat) — 이미 받은 시도 데이터를 브라우저에서 거름, 서버 요청 없음
[데이터 층] 공공데이터 원래 값: 업종 12개 · 한식 세부분류 8개 (손대지 않음)
```

| 층 | 책임 | 바뀌면 고치는 곳 |
|---|---|---|
| 데이터 | 원본 값 보존, 이상 값 감지 | 파이프라인·점검 스크립트(`check_data.py`) |
| 표시 | 사용자가 보는 분류, 세부 칩, 표시 이름 | 묶음 표(`app/app.js` `GROUPS`) 한 곳 |
| 언어 | 단어 사전, 상황어, 정규화, 지역 규칙 | `app/intro.js` 사전 |
| AI | 문장 → 데이터 값 조건 | 프롬프트·스키마(`functions/api/parse.js`) — 데이터 값이 안 바뀌면 그대로 |

## 2. 처리 흐름 예시

| 입력 | ① 규칙 | ② AI | ③ 변환·④ 필터 | 결과 |
|---|---|---|---|---|
| 강남 커트 | 지역 강남구, "커트" = 두 업종에 다 해당하는 말 | 호출 안 함(2개 읽음) | 미용·이발 묶음 전체 | 4곳 |
| 종로 이발소 | 지역 종로구, "이발소" = 구체적인 말 | 안 함 | 미용·이발 › 이용 | 3곳 |
| 대전 남자 이발 저렴한 데 | 지역만(1개) | 업종 이용업 + 검색어 "이발" | 검색어가 업종 단어 → 업종으로 바꿈, 사용자가 "이발"을 말했으니 세부 칩까지 | 미용·이발 › 이용 29곳 |
| 부산 막걸리 | 지역 + 사전에 없는 단어 하나 남음 → 검색어 | 안 함 | 업종 제한 없이 메뉴·업소명 검색 | 1곳 |
| 부산 매운탕 | 메뉴 단어 → 검색어만(업종 짐작 안 함) | 안 함 | 한식 + 일식 횟집 | 10곳 |
| 종로구 분식 3천원 이하 주차 | 세부분류·가격·주차 | 안 함 | 0곳 → 가격, 주차 순으로 풀어 다시 찾음 | 1곳 + "뺀 조건" 안내 |

## 3. 설계 원칙

### A. 분류 체계
1. **데이터는 원래 값 그대로, 분류는 화면 층에서 묶는다.** 원본을 바꾸면 분기 갱신마다 다시 바꿔야 하고 출처와 어긋난다. 원래 값은 세부 칩으로 살려 둔다. (#51)
2. **매핑 표는 한 곳에만 두고, 모든 진입점이 그 표를 쓴다.** 칩·홈 아이콘·추천 카드·문장 검색·AI 변환·카드 표시. 추천 카드는 두 업종을 보여 주는데 "→ 지도"는 한 업종만 걸러 이발소 353곳이 빠졌다. (#51, #50)
3. **새 값은 사라지지 않게 기본 묶음으로 보내고, 점검에서 알린다.** 앱은 모르는 업종을 "생활"로 보내고, `check_data.py`는 모르는 업종·세부분류를 FAIL로 알린다. (#51)
4. **바꾸기 전에 실제 데이터 숫자로 영향도를 본다.** 조회 요청·필터 조건·화면 표시를 나눠 확인한다. 서울 미용·이발 393곳이 475곳이 되고, "커피" 59곳 중 58곳이 카페·빵이라는 숫자가 "카페는 묶음 전체"라는 결정의 근거가 됐다.
5. **분류를 바꾸면 기존 빈틈이 드러난다.** 홈에서 갈 수 없던 업종(기타비요식업 466곳), 칩과 홈의 이름 불일치가 이번에 발견됐다. (#51)

### B. 자연어 해석(규칙)
6. **업종을 가리키는 말(카테고리어)과 메뉴를 가리키는 말(내용어)을 나눈다.** 업종은 사용자가 업종 단어를 말했을 때만 적용하고, 메뉴에서 업종을 짐작하지 않는다. "매운탕"을 한식으로 좁히자 일식 횟집이 빠졌다. (#48)
7. **말의 넓이에 맞춰 연결한다.** 두 업종에 다 해당하는 말(커트·헤어·카페·생활)은 묶음 전체, 구체적인 말(미용실·이발소·빵집·세탁·사우나·모텔)은 세부 칩까지. (#51)
8. **사용자가 입력한 단어는 버리지 않는다.** 사전은 보조이고 최종 기준은 데이터(메뉴·업소명)다. 짧은 검색(4단어 이하)에서 모르는 단어가 하나 남으면 검색어로 쓴다. (#50)
9. **사전 대조는 최장 일치, 사용자 단어가 더 길면 그대로.** 칼국수 > 국수, "콩국수"를 "국수"로 줄이지 않는다. (#4, #50)
10. **한 글자 검색어는 부분 일치로 쓰지 않는다.** 필요하면 앞뒤 글자 규칙을 둔다. '회'가 PT 10회권·마을회관·육회까지 잡았다 → 목록보다 규칙(`KW_RULES`)이 맞았다. (#5, #49)
11. **부분 일치 함정은 부정 전방탐색이나 구체어로 막는다.** 드라이브 → 세탁(드라이), 아이스크림 → 유아(아이). 정규화 결과가 다시 규칙에 걸리지 않게 한다(짜장면 → 짜장면면). (#17)
12. **상황어는 명시 조건이 없을 때만 채운다.** 해장 → 국밥, 회식 → 단체가능, 머리 자르고 싶어 → 미용·이발. 체감 품질을 크게 올린다.
13. **지역은 상위가 나오면 그 안에서만 찾는다.** 시도가 나오면 그 시도 안의 시군구만, 줄임말 사전(충남·전남…), 시도명과 같은 글자로만 잡힌 시군구는 제외(제주 ≠ 제주시), 동명 시군구는 현재 시도 우선. (#15, #16)
14. **숫자·단위는 아라비아와 한글 둘 다.** 1만5천원 / 만오천원. (#17, #47)

### C. AI 연결
15. **AI는 조건 변환만 하고 데이터는 보내지 않는다.** 검색은 앱이 로컬에서 한다 → 토큰 적음, 유출 없음, 모델 교체 쉬움.
16. **AI는 데이터 층의 값으로 말하게 하고, 화면 값으로 바꾸는 건 앱이 한다.** 분류 체계를 바꿔도 AI는 그대로. (#51)
17. **AI 답은 허용 목록으로 재검증한다.** 없는 업종·시설 무시, 가격 범위 제한, 사용자가 업종 단어를 말하지 않았으면 AI가 준 업종도 버린다(짐작 금지). AI가 업종 단어를 검색어로 주면 업종으로 바꾼다("커트" 검색어는 "컷트" 메뉴를 놓침). (#48, #51)
18. **AI가 준 검색어가 세부분류 이름이면 세부 칩으로 바꾼다.** '한정식'을 메뉴 이름에서 찾으면 0곳. (#43)
19. **AI 호출 안정화 다섯 가지:** 무작위성 0(`temperature 0`), 일시 오류(429·500·503) 서버 1회 재시도, 8초 제한 후 규칙 결과로 진행, 가장 최근 검색의 답만 적용, 실패 원인별 안내("AI가 잠시 안 돼요"). (#44~46)
20. **규칙 우선·AI 보조의 기준(읽은 조건 1개 이하 → AI)은 모든 진입점이 같아야 한다.** 인트로와 상단 검색창 기준이 달라 한쪽에서만 오류가 났다. (#50)

### D. 결과와 검증
21. **결과 0곳은 막다른 길이다.** 검색어 → 가격 → 시설·영업중 → 세부 칩 순으로 풀어 다시 찾고, 뺀 조건을 알려준다. (#43)
22. **해석 정확도와 결과 유무는 따로 테스트한다.** 해석은 맞는데 0곳인 경우가 가장 흔한 불만이었다. (#43)
23. **규칙 단어를 추가하면 처리 경로가 바뀔 수 있다.** AI로 가던 문장이 규칙으로 오면서 가격이 빠졌다 → 회귀 확인에 "어느 경로(규칙/AI)가 처리했나"를 넣는다. (#47)
24. **회귀 문장은 진입점별로 돌린다.** 인트로·상단 검색·홈. 목록은 [버그이력 부록](버그이력.md).
25. **두 해석기(규칙·AI)의 결과는 덮어쓰지 말고 합친다.** AI가 비운 칸은 규칙이 읽은 값으로 채운다(`mergeRule`). "싼 곳"의 가격이 AI 결과에서 빠졌다. (#52)
26. **애매한 말의 기준값은 분류별로, 앱의 다른 곳과 같은 값으로.** '싼·저렴·가성비'는 음식 5천 원, 미용·이발·생활 1만 원 — 홈 추천의 '착한가격' 기준과 같게(`vagueCheap`). (#52)
27. **조건을 이어받으면 알린다.** 문장에 지역이 없으면 보던 지역에서 찾고 "강남구(보던 지역)"으로 표시한다. (#52)
28. **넓은 말(음식 종류)과 좁은 말(메뉴)을 구분한다.** "닭요리"는 메뉴 이름이 아니라 종류 → 메뉴 묶음으로 찾고, 좁은 말("치킨")이 0곳이면 검색어를 빼기 **전에** 속한 묶음으로 넓힌다. 검색어를 통째로 빼는 완화는 마지막 수단(전체가 나오면 '조회가 안 된다'로 느낀다). (#55)

## 4. 착한가격 지도의 현재 매핑 (2026-09-22)

**업종 묶음** (`app/app.js` `GROUPS`)

| 칩 | 세부 칩(데이터 업종 값 → 표시) |
|---|---|
| 한식 | 세부분류 8개(일반·육류·면류·분식·찌개류·한정식·해산물·기타) |
| 중식 · 일식 · 양식 | 없음 |
| 카페·빵 | 기타요식업 → 카페·기타 / 베이커리 |
| 미용·이발 | 미용업 → 미용 / 이용업 → 이용 |
| 생활 | 세탁업 → 세탁 / 목욕업 → 목욕 / 숙박업 → 숙박 / 기타비요식업 → 기타(카드에는 "생활·기타") |

**단어 → 조건** (`app/intro.js`)

| 종류 | 예 | 적용 |
|---|---|---|
| 묶음 전체용 말 (`GROUP_WIDE_WORDS`) | 카페, 헤어, 커트, 컷트, 컷, 생활 | 묶음 칩만 |
| 구체적인 업종 말 (`CATEGORY_WORDS`) | 미용실, 이발소, 빵집, 제과, 세탁, 사우나, 모텔, 중국집 | 묶음 + 세부 칩(한·중·일·양식은 그 칩) |
| 메뉴 단어 (`UPJONG_WORDS`의 나머지) | 국밥, 짜장, 매운탕, 커피, 파마 | 검색어만(업종 제한 없음) |
| 상황어 (`SITUATION`) | 해장, 회식, 아이랑, 머리 자르고 싶어 | 명시 조건이 없을 때만 채움 |
| 정규화 (`NORMALIZE`) | 헤어샵 → 미용실, 커피숍 → 카페, 찌게 → 찌개 | 해석 전에 표준 표기로 |
| 남은 단어 (`leftoverWords`) | 막걸리, 마라탕 | 4단어 이하에서 하나 남으면 검색어 |
| 금액 없는 가격 말 (`VAGUE_PRICE`) | 싼, 저렴, 가성비, 혜자 | 음식 5,000원 / 미용·이발·생활 10,000원 이하 |
| 메뉴 묶음 (`MENU_GROUPS`, app.js) | 닭요리(닭·치킨·삼계·백숙), 오리요리, 생선요리, 돼지고기, 소고기 | 묶음에 속한 메뉴·업소명이 있는 음식점. 닭고기·닭집·'닭'·오리고기·쇠고기 등은 정규화. 좁은 말이 0곳이면 묶음으로 넓힘 |

| 기능 | 위치 |

## 5. 다른 프로젝트에 적용하는 순서

- [ ] 원본 분류 값 목록과 **값별 건수**를 뽑는다(작은 값·"기타"가 무엇을 담는지 샘플 확인 — 기타비요식업에는 필라테스·학원·안경원이 있었다)
- [ ] 사용자가 쓰는 말로 묶음을 정하고, 원래 값은 세부 칩으로 남긴다. **묶음 표는 한 곳**
- [ ] 단어 사전을 네 종류로 나눈다: 묶음 전체용 말 / 구체적인 분류 말 / 내용어(메뉴·품목) / 상황어
- [ ] AI 스키마는 **데이터 값**으로, 앱에서 허용 목록 재검증 + 화면 값 변환
- [ ] 규칙 먼저·AI 보조 기준을 정하고 모든 진입점이 같은 함수를 쓰게 한다
- [ ] 결과 0곳 완화 순서와 안내 문구를 정한다
- [ ] 새 값 대비: 앱은 기본 묶음으로, 점검 스크립트는 FAIL로
- [ ] 회귀 문장 목록(진입점별, 처리 경로 포함)을 만들고 실제 데이터 숫자를 기대값으로 적는다
- [ ] 분류를 바꿀 때는 영향도(조회 요청·필터 조건·화면 표시)를 숫자로 먼저 보고 목업으로 확인

## 8. 갱신 규칙

- 문장 검색·분류 관련 버그를 고치면: ① 버그이력에 사건 기록과 회귀 문장 추가 ② **새 원칙이 생기거나 기존 원칙이 바뀐 경우에만** 이 문서 3장·7장을 고친다.
- 매핑 표(묶음·단어)를 바꾸면 4장 표도 함께 고친다.
- 정기 지식화 점검(주간·분기 예약 작업)은 새 버그 번호가 이 문서 원칙에 반영됐는지 확인한다.
- 착한가격 지도 고유의 수치는 근거로만 두고, 원칙 문장은 다른 프로젝트에도 통하게 쓴다.
