## 상세

### 1. 코드를 고쳐도 브라우저에 반영 안 됨 `환경`
- **증상:** JS·CSS 수정 후 새로고침해도 옛 동작. 포트 8000에 예전 서버 프로세스가 남아 있기도 함.
- **원인:** 브라우저 캐시 + 중복 실행된 옛 `http.server`.
- **해결:** 서버에서 js/css/html에 `Cache-Control: no-store`, `index.html`의 파일 주소에 `?v=타임스탬프` 붙이기, 옛 프로세스 종료, 실행 설정을 `.claude/launch.json` 하나로 통일.
- **재발 방지:** 개발 서버는 캐시 금지 헤더를 기본으로. 수정 스크립트 끝에 버전 값 자동 갱신. **배포 때는 캐시 설정을 다시 켤 것.**

### 2. 카카오 지도 401 오류 `환경`
- **증상:** 지도 영역이 비고 콘솔에 401.
- **원인:** 카카오 개발자 콘솔에 접속 도메인(localhost:8000, 127.0.0.1:8000) 미등록.
- **해결:** 콘솔 → 플랫폼 키 → JavaScript 키 → 도메인 등록. 지도 실패 시 안내 화면(`#mapfallback`)에 등록할 주소 표시.
- **재발 방지:** 배포 주소, 휴대폰 테스트 주소(`http://192.168.x.x:8000`)도 등록 목록에 포함.

### 3. `hidden`이 안 먹음 `화면`
- **원인:** CSS의 `display` 지정이 `hidden` 속성보다 우선.
- **해결:** `[hidden]{display:none !important}` 규칙 추가.
- **재발 방지:** 새 프로젝트 기본 CSS에 포함.

### 4. "칼국수"가 "국수"로 인식 `해석`
- **원인:** 단어 목록을 앞에서부터 대조해 짧은 단어가 먼저 맞음.
- **해결:** 맞는 단어 중 **가장 긴 것** 채택.
- **재발 방지:** 사전 대조는 항상 최장 일치.

### 5. 회식 → 일식, "만원" 단독 미인식, 미용 키워드 `해석`
- **원인:** 일식 단어에 한 글자 "회"가 있어 "회식"에 걸림. 가격 규칙이 숫자가 있어야만 동작.
- **해결:** "회" 대신 "모둠회·생선회·회덮밥" 등 구체 단어 사용, "만원 이하" 단독 규칙 추가, 미용 동의어 보강.
- **재발 방지:** **한 글자 키워드 금지.** 새 단어를 넣으면 흔한 문장 예시로 오인식 테스트.

### 6. 상세 닫기·뒤로가기 꼬임 `화면`
- **원인:** 주소 갱신(`replaceState`)이 상세 열림 기록(`history.state`)을 지워 버림.
- **해결:** `replaceState(history.state, …)`로 기존 기록 유지, 닫기 버튼·목록 버튼·휴대폰 뒤로가기를 모두 `history.back()` → `popstate` 한 경로로 통일.
- **재발 방지:** 화면 상태를 주소 기록에 쓰면 닫는 경로를 하나로.

### 7. 목록 사진이 안 뜸 / 공식 서버 시간초과 `화면`
- **원인:** 지연 로딩과 투명도 전환이 겹쳐 안 보임 → 해결 후엔 수십 장을 동시에 요청해 공식 서버가 시간초과.
- **해결:** 화면에 들어온 사진만 요청(IntersectionObserver), 동시 요청 6개 제한 큐.
- **재발 방지:** 외부(특히 공공기관) 이미지는 동시 요청 제한 필수.

### 8. 모바일 지도가 엉뚱한 영역·깨짐 `지도`
- **원인:** 아래 목록 시트가 지도를 가리는 것을 고려하지 않음. 숨겨진 상태에서 지도를 만들어 크기가 0.
- **해결:** `setBounds`에 시트 높이만큼 아래 여백. 지도 화면으로 전환할 때 `relayout()` + 영역 맞춤.
- **재발 방지:** 숨김 상태에서 만든 지도는 보일 때 반드시 `relayout`.

### 9. 홈 → 지도 이동 시 세부업종 풀림 `화면`
- **해결:** 같은 업종이면 세부업종 유지(`goMapWith`).

- **원인:** ① 카카오톡 등 앱 안 브라우저에서는 설치(홈 화면 추가)·위치가 제한됨 ② 설치 창이 없을 때 안내가 작은 글씨로만 나와 놓치기 쉬움 ③ 앱 안 브라우저에는 기본 공유 창이 없음.
- **해결:** 앱 안 브라우저면 위쪽에 "브라우저로 열기" 안내(카카오톡은 `kakaotalk://web/openExternal`로 기본 브라우저 실행), 홈 첫 화면에 "홈 화면에 앱 아이콘 추가" 버튼, 설치 창이 없으면 기기별(크롬·삼성 인터넷·아이폰) 단계 안내 창. 상세에 카카오 공식 공유 버튼(Kakao SDK `Share.sendDefault`, 업소명·가격·사진·링크).
- **재발 방지:** 한국 사용자는 링크를 대부분 카카오톡에서 열므로, **카톡 안 브라우저를 필수 테스트 환경**으로.

### 41. 카카오톡 공유 링크가 안 열림 `환경`
- **증상:** 카카오 공유 카드(업소명·가격·사진)는 전송되지만 카드·버튼을 눌러도 반응 없음.
- **원인:** 카카오는 공유 메시지 안 링크의 도메인이 앱에 등록된 경우에만 링크를 넣음. JavaScript 키 도메인(지도·SDK용)만 등록돼 있었음.
- **해결:** 카카오 콘솔 → 앱 → **제품 링크 관리**에 `https://goodprice-map.pages.dev` 등록(새 콘솔 기준. "앱 대표 도메인"만으로는 해결 안 됨). 등록 후 **새로 보낸 메시지**부터 열림.
- **재발 방지:** 카카오 콘솔 도메인은 세 군데 — ① 플랫폼 키 → JavaScript 키 도메인(지도·SDK) ② 제품 링크 관리(공유 링크) ③ 앱 대표 도메인. 주소가 바뀌면(개인 도메인 등) 세 곳 모두 갱신.

### 42. 인트로 입력칸 잘림 `화면`
- **증상:** 실기기(글씨 크기를 키운 안드로이드)에서 인트로의 문장 입력칸이 오른쪽으로 넘쳐 전송(→) 버튼이 화면 밖으로 밀림.
- **원인:** 가로 배치(flex) 안의 입력칸은 기본 최소 폭이 "자기 글자 폭"이라 줄어들지 않음. 글씨가 커지면 그만큼 넓어짐. 인트로는 화면 고정·넘침 숨김이라 스크롤로도 볼 수 없었음.
- **해결:** 입력칸 `min-width:0; width:100%`, 인트로 세로 스크롤 허용(`overflow-y:auto`, `justify-content:safe center`, 하단 안전영역 여백), 예시 칩 줄바꿈 허용. 글자 15·22·28px에서 모두 화면 안에 들어오는 것 확인.
- **재발 방지:** 가로 배치 속 입력칸에는 항상 `min-width:0`. **휴대폰 글씨 크기 확대** 상태를 테스트 조합에 추가. 화면 고정 오버레이는 넘치면 스크롤되게.

### 43. AI 해석 결과 0곳 `해석`
- **증상:** "해운대 조용한 한정식 만오천원" → 해석은 정확(부산 해운대구·한식·'한정식'·15,000원)한데 0곳.
- **원인:** ① '한정식'은 앱의 한식 **세부분류**인데 메뉴 이름 검색어로 적용 ② 지역+가격+시설 조건이 겹치면 0곳이 되기 쉬움.
- **해결:** 검색어가 세부분류(한정식·분식·면류 등)면 **세부분류 칩으로 적용**(규칙·AI 공통). 결과가 0곳이면 **검색어 → 가격 → 시설·영업중 → 세부분류** 순으로 하나씩 풀어 다시 찾고 "○○ 조건은 결과가 없어 뺐어요" 안내.
- **재발 방지:** 해석 정확도와 **결과 유무**를 따로 테스트. 0곳은 사용자에게 막다른 길이므로 항상 대안 제시.

### 45. 늦게 온 이전 AI 답 `해석`
- **원인:** 첫 문장의 AI 응답이 늦게(7초+) 오는 사이 두 번째 문장을 검색 → 첫 응답이 나중에 적용되어 "조개찜"이 부산 해운대구로 검색됨.
- **해결:** 검색마다 순번을 매겨 **가장 최근 검색의 답만 적용**. AI 응답은 8초 넘으면 끊고 규칙 결과로 진행.
- **재발 방지:** 비동기 요청 결과를 화면에 반영할 때는 항상 "아직 최신 요청인가"를 확인.

### 46. AI 일시 오류 안내 `해석`
- **원인:** 제미나이가 과부하·한도로 502/503을 가끔 반환(테스트 중 2회). 그때 규칙도 못 읽으면 "조건을 못 읽었어요"로 잘못 안내.
- **해결:** 서버에서 429·500·503이면 0.8초 뒤 **한 번 재시도**, 그래도 실패하면 "AI 해석이 잠시 안 돼요. 잠시 뒤 다시 시도…"로 구분 안내.

### 47. 한글 숫자 가격 `해석`
- **원인:** 가격 규칙이 아라비아 숫자(5천원·1만5천원)만 인식. '한정식'을 규칙 단어로 추가하자 AI 대신 규칙이 처리하게 되면서 "만오천원"이 빠짐(규칙 보강이 다른 경로를 바꾼 사례).
- **해결:** 한글 숫자 규칙 추가(오천원·만오천원·이만원·만 이천 원 → 5,000·15,000·20,000·12,000).
- **재발 방지:** 규칙 단어를 추가하면 **AI로 가던 문장이 규칙으로 바뀌는지** 회귀 문장으로 확인. 숫자·단위 표현은 아라비아·한글 두 방식 모두 테스트.

### 48. 메뉴 검색에 업종 짐작 `해석`
- **증상:** "부산 매운탕" → 9곳. 메뉴에 매운탕이 있는 부산 업소는 10곳이고, 빠진 곳은 **일식으로 등록된 횟집**. 규칙도 "돈까스 → 일식", "짜장면 → 중식", "국밥 → 한식"처럼 메뉴에서 업종을 짐작해 붙이고 있었음.
- **원인:** 사용자가 말하지 않은 업종을 규칙·AI가 **짐작해 필터로 적용**. 같은 메뉴를 여러 업종이 판다(분식집 돈까스, 횟집 매운탕).
- **해결:** 업종은 **사용자가 업종 단어를 말했을 때만** 적용(한식·중식·미용실 등). 메뉴 단어는 검색어로만 써서 모든 업종의 메뉴에서 찾음. 업종 단어와 메뉴 단어는 따로 인식("중식 짜장면" → 중식 + 짜장). AI 답도 문장에 업종 단어가 없으면 업종을 적용하지 않음. 자주 찾는 메뉴(매운탕·해물탕·감자탕·삼계탕·설렁탕·생선구이·보쌈·족발 등)를 규칙에 추가해 AI 없이 즉시 처리.
- **결과:** 부산 매운탕 10곳(한식+일식), 돈까스 5천원 이하 19곳(한식·중식·양식).
- **재발 방지:** "사용자가 말한 조건"과 "시스템이 짐작한 조건"을 구분하고 **짐작은 필터로 쓰지 않는다.** 누락 검증은 "그 메뉴가 있는 전체 업소 수"와 대조.

### 49. 한 글자 검색어 '회' `해석`
- **증상:** "바다 보면서 회 먹을 만한 곳" → AI가 검색어 '회'를 주자 부산 41곳, 그중 PT 10회권·족욕 1회권 등 비음식 업소 포함.
- **원인:** 한 글자 검색어는 다른 단어의 일부로 흔히 나온다(10회, 회관, 상회, 회비, 다회용기, 육회).
- **해결:** '회'는 규칙으로 판별 — 메뉴 이름의 '회'(생선회·멸치회·회국수·회덮밥·회비빔밥)만 인정하고 숫자 뒤·육회·다회·회관·상회·회사·회원·회차·회당·회비(회비빔 제외)는 제외, 업소명은 횟집·회센터·활어만. 전국 248곳(한식·일식 위주, 비음식 0).
- **처음 시도(단어 목록)의 한계:** 활어·모둠회 등 목록으로 찾으면 멸치회·회국수·명태회김밥이 빠졌다 → **목록보다 규칙(앞뒤 글자 조건)** 이 맞았다.
- **재발 방지:** 한 글자 키워드는 규칙 없이 부분 일치로 쓰지 않는다(버그 #5의 확장). 새 한 글자 키워드는 `KW_RULES`에 판별 규칙을 둔다.

### 50. 사전에 없는 메뉴가 사라짐 `해석`
- **증상:** 첫 화면(인트로)에서 "부산 막걸리" → 부산 전체 1,284곳. 상단 검색창에서는 AI가 받아 1곳으로 정상이라 발견이 늦었다.
- **원인:** ① 규칙은 사전에 없는 단어("막걸리")를 버리고 아는 것(부산)만 적용 ② **인트로와 상단 검색창의 AI 호출 기준이 달랐다** — 상단은 "규칙이 1개 이하만 읽으면 AI", 인트로는 "0개일 때만 AI" → 인트로는 지역만 읽고 끝냄.
- **해결:** ① **남은 단어 → 검색어:** 4단어 이하 짧은 검색에서 지역·가격·조건·흔한 말(곳·맛집·먹을…)·조사를 빼고 모르는 단어가 하나 남으면 메뉴·업소명 검색어로 사용(사전 없이도 모든 메뉴 검색) ② 사용자가 쓴 단어가 사전 단어보다 길면 그대로(콩국수 ⊃ 국수, 칼국수집 → 칼국수) ③ 인트로도 상단과 같은 기준(1개 이하 → AI), AI 실패 시 규칙이 읽은 것이 있으면 그걸로 진행.
- **재발 방지:** 같은 기능의 **진입점이 여럿이면(인트로·상단 검색·홈) 같은 함수·같은 기준**을 쓴다. 회귀 테스트는 진입점별로. "사용자가 입력한 단어가 결과에 반영됐는지"를 확인(버려진 단어가 없는지).

### 51. 업종 묶음 적용 중 발견한 누락 `해석` `화면`
- **배경:** 2026-09-22 업종 칩 13개를 8개로 묶음(카페·빵 = 기타요식업+베이커리, 미용·이발 = 미용업+이용업, 생활 = 세탁·목욕·숙박·기타비요식업). 데이터 업종 값은 그대로 두고 화면에서만 묶는다(app.js `GROUPS`).
- **함께 드러난 기존 문제:** ① 홈의 "미용·이발" 추천 카드는 미용·이발을 함께 보여 주는데 "→ 지도"는 미용업만 걸러 **이발소 353곳이 빠짐** ② 기타비요식업 466곳(필라테스·학원·안경원 등)은 **홈 아이콘에 없어 들어갈 길이 없음** ③ 상단 칩은 "카페·기타", 홈은 "카페"로 **이름이 달랐음** ④ "커트"·"머리 자르고 싶어"가 미용업만 찾음(이발소 누락), AI가 검색어 '커트'를 주면 '컷트' 표기 메뉴를 놓침.
- **해결:** 묶음 표 하나(`GROUPS`)를 칩·홈 아이콘·추천·문장 검색·AI 변환·카드 표시가 모두 사용. 두 업종에 다 해당하는 말(카페·헤어·커트·컷트·생활·머리)은 묶음 전체, 구체적인 말(미용실·이발소·빵집·세탁·사우나·모텔…)은 세부 칩까지. AI가 업종 단어를 검색어로 주면 업종으로 바꿈. 묶음에 없는 새 업종은 생활로(사라지지 않게), `check_data.py`가 모르는 업종·한식 세부분류를 FAIL로 알림.
- **재발 방지:** 분류 기준은 **한 곳에만 두고 모든 진입점이 그 표를 쓴다**(#50과 같은 원칙). 추천 카드의 목록 조건과 "→ 지도" 조건이 같은지 확인.

### 52. AI가 빠뜨린 조건, 금액 없는 "싼"의 기준 `해석`
- **증상:** ① "부산에서 머리 다듬을 만한 싼 곳"을 AI가 해석하면 가격 조건이 없음(규칙은 '싼' → 5천 원을 읽었는데 AI 결과로 통째로 바꿈) ② 업종 묶음 이후 "대전 남자 이발 저렴한 데"가 규칙으로 처리되면서 '저렴' → 5천 원 → 1곳(이발 커트는 대개 5천 원 초과) ③ "머리 자르고 싶어"처럼 지역이 없으면 보던 지역(예: 강남구)에서 찾는데 결과 문구에 지역이 없음.
- **원인:** ① AI 결과가 규칙 결과를 **덮어씀**(합치지 않음) ② 금액 없는 '싼'의 기준이 음식 기준(5천 원) 하나 ③ 지역 유지는 의도한 동작이지만 안내가 없었음.
- **해결:** ① `mergeRule`: AI가 비운 칸(지역·동·가격·업종·검색어·조건)은 규칙이 읽은 값으로 채움 ② `vagueCheap`: 금액 없는 '싼·저렴·가성비'는 음식 5천 원, 미용·이발·생활 1만 원(홈 추천의 '착한가격' 기준과 같게) ③ 지역이 없으면 "강남구(보던 지역)"으로 표시.
- **재발 방지:** 두 해석기(규칙·AI)의 결과는 **덮어쓰지 말고 합친다**. 애매한 말(싼)의 기준값은 **분류별로**, 그리고 앱의 다른 곳(홈 추천)과 같은 값을 쓴다.

### 53. 분기 갱신의 변경 미반영·오등록 위험 `데이터`
- **발견:** 사용자 질문("갱신되면 기존·추가·변경을 어떻게 구분하나, 밀려서 다른 업체 정보가 교차 등록되지 않나")을 계기로 코드를 점검. 실제 분기 갱신 전에 발견.

- **재발 방지:** 분기 변경 분류 보고서에 "CSV에만 있음"을 확인 목록으로 매번 올린다(기본 결정: 숨김). 사유는 추정이므로 내부 기록만, 화면에는 표시하지 않는다.

### 55. 음식 종류를 넓게 말하면 전체가 나옴 `해석`
- **증상:** "속초 닭요리" → 속초 전체 58곳(실제 닭칼국수·숯불닭갈비·숯불닭구이 3곳). "속초 닭"은 한 글자라 버려지고, "속초 치킨"·"통닭"은 그 이름의 가게가 없어 전체.
- **원인:** ① "닭요리"는 메뉴 이름이 아니라 **음식 종류**인데 메뉴 이름 부분 일치로 찾아 0곳 ② 결과 0곳이면 검색어를 빼는 완화(#43)가 곧바로 전체를 보여 줌 ③ 한 글자 단어 제외 규칙(#5)이 '닭'을 버림.
- **해결:** 메뉴 묶음(`MENU_GROUPS`: 닭요리·오리요리·생선요리·돼지고기·소고기) — 묶음에 속한 메뉴·업소명이 있는 **음식점**을 찾음(세탁소 '오리털' 제외). "닭고기·닭집·닭(한 글자)·오리고기·쇠고기" 등은 표준 이름으로 정규화(AI 검색어도). 결과 0곳이면 검색어를 빼기 **전에** 속한 묶음으로 넓힘("'치킨' → 닭요리 전체로 넓혔어요").
- **재발 방지:** 검색어를 빼는 완화는 마지막 수단. 넓은 말(종류)과 좁은 말(메뉴)을 구분하고, 좁은 말이 없으면 먼저 넓은 말로 올라간다.

### 56. 카드 가격과 메뉴가 짝이 안 맞음, 가격 기준이 곁메뉴 `화면`
- **발견:** 사용자의 정렬 선택 제안("거리순 말고 다른 정렬도")을 검토하다 코드에서 발견.
- **증상:** 카드에 "4,000원 닭곰탕"(닭곰탕은 9,500원, 4,000원은 야채김밥) — 12,899곳 중 3,561곳(27.6%). 가격순·"N원 이하"·홈 "5천원 이하 한 끼"도 가게의 가장 싼 메뉴(곁메뉴·0원 입장료 포함) 기준이라 "칼국수"를 찾아도 칼국수 가격이 아닌 다른 메뉴로 정렬·필터.
- **원인:** 데이터의 `p`(가장 싼 메뉴 가격)와 `m[0]`(첫 메뉴)을 따로 가져와 한 줄에 붙였다.
- **해결(사용자 결정 A안):** 가격과 메뉴를 **한 쌍으로** 고른다 — 검색어가 있으면 그 메뉴 중 가장 싼 것(메뉴 묶음·'회' 규칙 포함), 없으면 **착한가격 지정 메뉴 중 가장 싼 것**(없으면 전체 중 가장 싼 것). 0원은 제외. 카드·가격순·가격 필터·홈 추천·PC 말풍선·저장 목록·공유 문구·카카오톡 미리보기가 같은 기준. 카드에 "지정 메뉴" 표시.
- **함께 바꾼 것:** 정렬 버튼을 누르면 3가지 선택(거리순 · 가격 낮은순 · 지금 영업 중 먼저). 기준 위치가 없으면 가격 낮은순이 기본이고 거리순은 흐리게 안내, 위치를 정하면(직접 고른 정렬이 없을 때) 거리순으로 자동 전환.
- **재발 방지:** 화면에 함께 보이는 값(가격·메뉴 이름)은 **같은 레코드에서 한 번에** 고른다. 대표값 계산 함수는 하나(`repMenu`·`shownMenu`)로 두고 모든 곳이 쓴다.

### 57. 어두운 모드 깜빡임·주소창 색, 글씨 크기 설정 없음 `화면`
- **발견:** [보기 설정·접근성](보기설정-접근성.md) 모듈을 두 번째 앱(이 앱)에 적용하며 규약과 대조.
- **증상:** ① 기기가 어두운 모드면 열 때마다 밝은 화면이 잠깐 보인 뒤 어두워짐 ② 어두운 모드에서도 주소창·상태바가 파랑(#1241BC) ③ 글씨 크기는 휴대폰 설정에만 기댐 — CSS 크기 값 737개가 전부 px라 루트 글씨를 바꿔도 따라오지 않음 ④ 누르는 자리 44px 미만 다수(칩 35px, 기준 위치 ✕ 22px, 상세 닫기 34px, 가격 슬라이더 16px).
- **원인:** ① `<html data-theme="light">`로 시작하고 저장된 설정은 본문 끝 `app.js`의 `initTheme`에서야 입힘 ② `theme-color`를 바꾸는 코드 없음 ③④ 처음에 px로 만들었고, 크기 규약이 없던 때.
- **해결:** `<head>`에 첫 페인트 전 적용 스크립트(`themeMode`·`textSize`) · `setTheme`이 `theme-color`도 바꿈 · CSS px 737개 중 563개를 rem으로 일괄 변환(1~2px 선, 그림자, 300px 이상 화면 뼈대, 미디어 쿼리는 px 유지) · 글씨 3단계(16/18/20px) · '가' 버튼(홈·지도 머리, PC는 지도로 시작하므로 PC 머리에서도 숨기지 않음)으로 보기 설정 시트, 더보기에도 글씨 크기 · 44px 보강(글 속 작은 버튼은 `::after`로 누르는 자리만 넓힘) · 어두운 모드 지도 `brightness(.88)` · 목록 시트 기본 높이를 본문 기준으로 바꿔 지도가 가려지지 않게.
- **재발 방지:** 새 화면은 `어둡게` + `아주 크게`로 한 번씩 본다. 확인 스크립트: 가로 스크롤(`scrollWidth > clientWidth`) + 44px 미만 누르는 요소 목록 — 휴대폰·태블릿·PC × 보통·아주 크게에서 0건.

### 58. 시군구를 이름으로 묶어 개편 뒤 옛·새 이름이 섞임 `데이터` `화면`
- **발견:** 장학금 세션이 행정구역 코드표(`../공통지식/기준자료/행정구역`)를 만들며 착한가격 인천 데이터를 대조.
- **증상:** 인천 시군구 선택에 중구 50·동구 33·서구 81과 제물포구 5·서해구 4·검단구 2가 **따로** 나옴(같은 동네가 두 칸). 원천 목록이 개편 전·후에 나뉘어 올라온 탓. 시군구 필터·홈 기준점·문장 검색이 모두 이름 비교(`it.g === S.sgg`).
- **원인:** ① 시군구를 **원천이 적은 이름 그대로** 썼다 ② 정제 결과에 코드 칸이 없었다(다섯 가지 키 점검에서 '법정동코드 없음').
- **조사 중 알게 된 것(계획이 바뀜):** "건물관리번호 앞 10자리 = 법정동코드"로 호출 없이 복원하려 했으나 **캐시의 20.1%(2,513곳)는 앞자리가 지금 없는 코드**(강원 42·전북 45·전남 46·광주 29·미추홀 28170…), 청주 43113처럼 **지금도 있는 코드가 다른 구**를 가리키기도 함 → 번호의 앞자리는 발급 당시 값. 원칙은 [공공데이터 파이프라인](공공데이터-파이프라인.md) 5-2.
- **함께 잡은 것:** GP09569(인천 동구 중앙로 15)의 주소 검증이 '정상(정제후)'인데 실제로는 **광주 동구 중앙로246번길 15**를 잡고 있었다(도로명+건물번호만으로 재조회). 새 검사(코드의 시도 ≠ 파일의 시도)가 첫 실행에서 찾음.
- **해결:** `region_codes.py` — 주소 정제 결과의 **현재 이름**(주소 API가 2026-09에 돌려준 시도·시군구) → 공통 코드표 → 시군구코드(97.8%). 이름이 없으면 원문 → `codes_of()`, 인천 옛 중구·서구는 읍면동으로 가르고 좌표로 검증(1.0%). 시도가 다른 주소 API 결과는 버림. 법정동코드는 건물관리번호 앞자리가 시군구코드와 같을 때만(10,076곳). 정제 결과(`app_data`)에 `시군구코드·필터코드·법정동코드·건물관리번호·코드출처` 칸. 앱은 `gc`(필터코드)로 거르고 이름은 코드에서 현재 이름으로 다시 붙임(주소 원문은 그대로). 옛 이름으로 찾으면 새 구 묶음("중구(현 제물포구·영종구)"). `check_data.py` 5-1: 코드 없음·옛 코드·시도 불일치·한 이름 여러 코드 → FAIL.
- **재발 방지:** 지역은 **이름이 아니라 코드**로 묶는다. 코드는 현재 이름에서 얻고, 번호 안에 박힌 코드를 잘라 쓰지 않는다. 옛 이름이 새 구 여럿이면 가른 뒤 좌표로 확인한다.

### 59. 좁은 화면 + 가장 큰 글씨에서 설정 버튼이 화면 밖으로 `화면`
- **발견:** #58 배포 전 `../공통지식/체크리스트/배포전.md`의 "어둡게 × 가장 큰 글씨 × 320px" 점검.
